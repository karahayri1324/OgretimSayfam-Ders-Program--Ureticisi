# FET Entegrasyonu

## Genel

FET, Liviu Lalescu tarafından yazılmış AGPLv3 lisanslı bir constraint satisfaction çözücüsüdür. Bizim için motor görevi görür: XML giriş alır, XML/HTML timetable çıkartır.

## CLI Kullanımı

```bash
fet-cl --inputfile=okul.fet \
       --outputdir=/path/to/out \
       --language=tr \
       --timelimitseconds=120 \
       --htmllevel=2 \
       --writetimetablesxml=true \
       --writetimetablesdayshorizontal=true \
       --writetimetablesteachers=true \
       --writetimetablesrooms=true \
       --printactivitytags=false
```

## Activity Modeli (Önemli!)

FET'in farklı bir mantığı var: **bir dersin haftada N saat olması**, N tane ayrı `<Activity>` demektir ve hepsi aynı `Activity_Group_Id`'yi paylaşır.

Örnek: 9A sınıfı Ahmet hoca'dan haftada 4 saat matematik alıyorsa:
- 4 ayrı `<Activity>` yaratılır
- Hepsinin `Activity_Group_Id` aynı (örn: 100)
- Her birinin `Duration=1, Total_Duration=4`
- Çift saat ders (block) için: 1 Activity ama `Duration=2`

**Bizim DB'de:** `activities` tablosunda 1 satır `{class: 9A, subject: Matematik, teacher: Ahmet, weekly_hours: 4, block_duration: 1}`. XML builder bunu 4 ayrı `<Activity>`'ye expand eder.

### Split Activities (v2)

`activities.split_group_id` aynı olan iki/daha fazla aktivite, FET'te
`ConstraintActivitiesSameStartingTime` ile aynı saatte koşmaya zorlanır.

Bu özelliğin tek başına yeterli olmadığı bir kısıt vardı: FET aynı `<Students>`
referansına sahip iki aktivitenin çakışmasına izin vermez. Bu yüzden split
senaryosunda XML builder otomatik olarak şunu yapar:

1. Bir sınıf split_group'lara katılıyorsa, o sınıfın Students_List girdisinde
   paralellik derecesi kadar `<Subgroup>` yaratılır (örn. `9A_g1`, `9A_g2`).
2. Split aktivitelerin `<Students>` alanı paylaştıkları subgroup'a göre
   indekslenir (`9A_g1`, `9A_g2`, ...).
3. Split olmayan aktiviteler hala Group adına (`9A`) atanır — FET bu durumda
   tüm subgroup'ları kapsar, eski davranış korunur.
4. Sınıf split'siz ise tek `9A_s` subgroup'u yazılır (eski davranış).

Bunun sonucu: aynı saatte iki ders, farklı öğretmen ve farklı oda — sınıf
fizik olarak iki gruba ayrılıyor.

### Per-day Hours (v2)

`day_hours` tablosu bir günün saat sayısını ve aralıklarını override eder.
FET tarafında MVP yaklaşım:

- Builder tüm günlerin saat sayılarının maksimumunu alıp tek bir `Hours_List`
  üretir. Hours adı global `hours`'tan alınır, eksik kalırsa override'larda
  geçen ilk isim veya jenerik `"N. Ders"` kullanılır.
- Kısa günlerde (örn. Cuma 7, global 8) eksik saatler için tek bir
  `ConstraintBreakTimes` node'u eklenir. İçinde tüm (Day, Hour) kombinasyonları
  listelenir; bu slot'lara FET hiç aktivite yerleştirmez (öğretmen + sınıf +
  oda hepsi blok).
- `day_hours.start_time` / `end_time` UI display içindir; FET'e gönderilmez.

## XML Üretim Stratejisi (xml-builder.ts)

```typescript
function buildFetXml(school: School): string {
  const doc = createXmlBuilder();
  doc.declaration({version: '1.0', encoding: 'UTF-8'});
  const root = doc.ele('fet', {version: '6.8.5'});

  root.ele('Institution_Name').txt(school.name);
  root.ele('Comments').txt('Generated by Ders Program Oluşturucu — ÖğretimSayfam');

  buildDaysList(root, school.days);
  buildHoursList(root, school.hours);
  buildSubjectsList(root, school.subjects);
  buildTeachersList(root, school.teachers);
  buildStudentsList(root, school.classes);
  buildActivitiesList(root, school.activities);  // expand to individual Activities
  buildRoomsList(root, school.rooms);
  buildTimeConstraints(root, school.constraints.time);
  buildSpaceConstraints(root, school.constraints.space);

  return doc.end({prettyPrint: true});
}
```

## Runner Stratejisi (runner.ts)

```typescript
async function runFet(fetFilePath: string, opts: RunOpts): Promise<FetResult> {
  const outDir = await mkdtemp('/tmp/dpo-');
  const binary = getFetBinaryPath();  // platform-specific bundled path
  const args = [
    `--inputfile=${fetFilePath}`,
    `--outputdir=${outDir}`,
    `--language=tr`,
    `--timelimitseconds=${opts.timeLimit ?? 120}`,
    `--htmllevel=2`
  ];

  return new Promise((resolve, reject) => {
    const proc = spawn(binary, args);
    let stdout = '', stderr = '';

    proc.stdout.on('data', d => {
      stdout += d;
      opts.onProgress?.(parseProgress(d.toString()));  // emit progress
    });
    proc.stderr.on('data', d => { stderr += d; });

    proc.on('exit', async code => {
      if (code === 0) {
        const tt = await parseTimetable(outDir);
        resolve({ ok: true, timetable: tt, outputDir: outDir });
      } else {
        const errFile = await readErrorFile(outDir);
        resolve({ ok: false, error: errFile || stderr || 'Bilinmeyen hata' });
      }
    });

    // cancel support
    opts.signal?.addEventListener('abort', () => proc.kill('SIGTERM'));
  });
}
```

## Output Parsing

FET, `outputdir`'a şunları yazar:
- `<base>_data_and_timetable.fet` — final FET dosyası
- `<base>_subgroups.xml` — sınıf bazlı timetable XML
- `<base>_teachers.xml` — öğretmen bazlı timetable XML
- `<base>_rooms.xml` — derslik bazlı timetable XML
- `<base>_activities.xml` — activity bazlı (activity_id → day/hour eşleşmesi)
- HTML dosyaları (görüntüleme için)

Bizim parser `activities.xml`'i okur, her activity'nin hangi gün/saatte olduğunu bulur, JS yapısına dönüştürür.

```typescript
type TimetableSlot = {
  activityId: number;
  day: number;       // 0-indexed
  hour: number;      // 0-indexed
  teacher: string;
  subject: string;
  students: string;
  room: string | null;
};
type Timetable = TimetableSlot[];
```

## Binary Bundling Stratejisi

### Build sırasında

```yaml
# electron-builder.yml
extraResources:
  - from: resources/bin/${os}/
    to: bin/
    filter: ["**/*"]
```

### Runtime'da
```typescript
function getFetBinaryPath(): string {
  const platform = process.platform;  // 'linux' | 'win32' | 'darwin'
  const name = platform === 'win32' ? 'fet-cl.exe' : 'fet-cl';
  const dev = process.env.NODE_ENV === 'development';
  const base = dev
    ? path.join(__dirname, '..', 'resources', 'bin', platform)
    : path.join(process.resourcesPath, 'bin');
  return path.join(base, name);
}
```

### Geliştirme sırasında
Sistemde yüklü `/usr/bin/fet-cl`'yi kullan. Production build'de bundled binary.

## Hata Senaryoları

| Hata | FET Çıktısı | Bizim Mesajımız |
|---|---|---|
| Çözüm bulunamadı | stdout: "Could not generate" | "Kısıtlamalar çok sert, çözüm bulunamadı. Bazı kısıtlamaları kaldırın veya esnetin." |
| XML parse hatası | exit code !=0, stderr | "Veride hata var. Lütfen geliştiriciye bildirin." (log dosyası) |
| Binary bulunamadı | spawn ENOENT | "FET motoru bulunamadı. Uygulamayı yeniden yükleyin." |
| Timeout | exit code on signal | "Çözüm uzun sürdü, zaman aşımı. Süreyi uzatın veya kısıtlamaları gevşetin." |
